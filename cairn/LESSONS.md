# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NN>): <lesson>`. One cap
(tracking-rules weight-caps): 50 lines, met by retiring or pruning entries.
Current knowledge: a lesson proven false is corrected in place (D-045).
Lessons also *leave*: one retires when a test fails on the mistake it warns
about, when another file's slot owns its content, or when a matured family
graduates whole into a doctrine module; pruning the stalest is the last resort
rather than the first (D-051, D-055).

- 2026-08-07 (M06): `tools::file_path_as_absolute()` resolves the macOS `/var` → `/private/var` symlink, so a test comparing a returned path against a bare `tempdir()` path fails — canonicalize the expectation, not the code.
- 2026-08-07 (M09, retiring the M06/M08 executability lesson): `Sys.which()` was MEASURED on GitHub runners rather than reasoned about, twice having been guessed wrong. Unix resolves an existing file iff `file.access(path, 1L) == 0`, extension irrelevant. Windows resolves it iff it carries any extension — `.txt` resolved at 0755 while `file.access()` said -1, so mode plays no part there — or, extensionless, iff a `.com`/`.exe`/`.bat`/`.cmd` sibling exists, and it returns that sibling's path. A `.txt` sibling does not resolve although a `.txt` file named directly does: the two rules are different, and reading one off the other is how the sibling set got written as `.exe` alone. So a Windows test fixture must carry an extension, and `test-helper-boundary.R` now fails on the mistake the old lesson only warned about.
- 2026-08-07 (M08): `usethis::use_github_action()` also adds a badge to README.Rmd, so the run must be followed by `devtools::build_readme()` — and the badge text adds a new spelling hit (`CMD`) that belongs in `inst/WORDLIST`.
- 2026-08-07 (M08): `gh` resolves the target repo from the working directory, so a loop that `cd`s to a scratch dir returns empty output for every job — which reads as "evidence absent" rather than "fetch failed". Keep `gh` calls in the repo root and write to absolute paths.
- 2026-08-07 (M08): `r-lib/actions/check-r-package@v2` already defaults `error-on` to `"warning"` and sets `_R_CHECK_FORCE_SUGGESTS_=false` itself, so the stock `check-standard` workflow needs neither line — read the pinned action's `action.yaml` (not `action.yml`) before adding one.
- 2026-08-07 (M06): the spelling NOTE's word list differs between `spelling::spell_check_package()` on the source and the tarball's `spelling.Rout` diff — compare branch against the default branch with one method rather than matching a remembered count, and check new roxygen/NEWS prose before committing.
- 2026-08-07 (M07): `testthat::local_mocked_bindings(.package = "stats")` does not intercept a generic openac *imports* — the package's imports environment resolves the binding first, so dispatch reaches the real generic and fails with "no applicable method". Mock in openac's own namespace (omit `.package`) to shadow an imported function.
- 2026-08-07 (M07): `list.files(recursive = FALSE)` returns directories alongside files (the recursive form omits them), and `file.exists()` is TRUE for a directory — so any extension-matched listing that feeds a per-file operation must filter with `!dir.exists()`, or a directory named `clips.mp4` is handed to the tool as input.
- 2026-08-07 (M09): `normalizePath(p, mustWork = FALSE)` returns a path it cannot resolve *unchanged*, so `identical(p, normalizePath(p, mustWork = FALSE))` is not an absoluteness test — it is TRUE for every relative path that does not exist. Match the three absolute forms explicitly (POSIX, UNC, Windows drive).
- 2026-08-07 (M09 review): a probe that materializes every fixture in one directory cannot say which one answered. M09's first `Sys.which()` probe created `tool` and `tool.exe` side by side, so the extensionless file resolved every query, the sibling rule was never observed, and the criterion written from it was inferred — shipping a branch an earlier guard made unreachable, with the wrong sibling set. Give each case its own directory holding exactly one file.
- 2026-08-08 (M09 review): an R default argument is a promise forced ONCE, at first use, and cached — so a factory whose default reads mutable global state (`os = Sys.info()[["sysname"]]`) pins that state at the returned closure's first call, not at each call. A test that fakes the environment afterwards is then silently ignored. Default such a parameter to `NULL` and resolve it inside the body on every call.
- 2026-08-08 (M10): testthat's own discovery and ordering fields are not the convention they look like — `find_test_scripts()` matches `^test.*\.[rR]$`, so `test_foo.R` and `testbare.R` both run, and `find_test_start_first()` reads `Config/testthat/start-first` with a HYPHEN. A guard written against `^test-` or `start_first` passes forever while the thing it guards walks past it; read the internal rather than assuming.
- 2026-08-08 (M10): `utils::getSrcFilename(substitute(code))` names the file an expression was WRITTEN in, not the file executing — a test generated by a `helper-*.R` function is attributed to the helper, and its real file reads as never run. To answer "which test file is running", read `path` from testthat's `source_file()` frame on the call stack.
- 2026-08-08 (M10): `packageDescription("openac")` returns a bare `NA` when the package is not installed, so `$"Config/testthat/parallel"` errors with "$ operator is invalid for atomic vectors". A test reading package metadata needs `devtools::load_all()` first — a bare `testthat::test_file()` is not enough.
- 2026-08-08 (M11): R keeps the parentheses of an immediately-invoked function expression in the AST — `(function() f())()` parses to a call whose HEAD is a `(` call wrapping the `function` node, not the node itself. A walker that asks "is this call's head a function definition" must unwrap `(` first; the first fix for exactly this missed both `(function() ...)()` and `(\() ...)()` until the fixture caught it.
- 2026-08-08 (M11): `R CMD check` sets `_R_CHECK_PACKAGE_NAME_` to the package name in the environment the test process sees, and leaves `NOT_CRAN` empty — MEASURED on a throwaway package, since neither is documented as a contract. Useful for a test that must know it is running under check, but it fails open: if a future R stops setting it, a conditional keyed on it passes vacuously forever, so it belongs beside a static check rather than carrying a guard alone.
- 2026-08-08 (M12): a narrative count written beside a script-computed table is where the drift lands, not the table. M12's 33-row and 8-row ledgers were both derived by script and both correct, while every prose figure summarizing them was wrong — "twelve of the 33" was ten, "the ten rows above" introduced eleven — and one of them became the first load-bearing reason of a D-entry. Derive the summary figure from the table in the same pass, or name the members instead of counting them.
- 2026-08-08 (M12): a sibling repo read for a cross-repo comparison moves under you — tidymedia advanced two commits during M12's own planning session. Pin BOTH sides by commit SHA in the provenance block, not just the one being assessed, and use the references-page snapshot `Extraction:` form so the page ages honestly rather than reading as current forever.
- 2026-08-08 (M11): review subagents share the primary working tree, so a destructive mutation check run while one is reading surfaces in its report as a phantom non-reproducible test failure — M11's blame reviewer reported exactly the failure the AC5 mutation was producing thirty seconds earlier. Run mutation checks when no subagent is live, or expect to spend the time attributing the ghost.
- 2026-08-08 (M13): `system2()` does NOT quote its `args` — it pastes them into a command string the shell re-splits, so `args = c("-i", "a b.mp4")` reaches the tool as three arguments. Quoting is the caller's job; do it once at the boundary with `shQuote()` per token, never by interpolating literal quotes at each call site (that form survives a space and loses to a `$`, which expands inside double quotes).
- 2026-08-08 (M13): `shQuote()` picks its quoting style for the whole VECTOR, not per element, and switches from `'...'` to `"..."` whenever any element contains an apostrophe — MEASURED: `shQuote(c("-i", "Jeff's.mp4"))` double-quotes BOTH elements while `shQuote("-i")` alone single-quotes. So any code deriving "the quote character" from a sample, or comparing a recorded token against a separately-quoted scalar, is wrong on apostrophe-bearing paths. Both mistakes shipped in M13 and one aborted correct calls.
- 2026-08-08 (M13; **corrected 2026-08-08 by M15's measurement — the quoting half held, the conclusion did not**): on Windows `shQuote(type = "cmd")` does not escape `%`, `^`, `&` or `!` — MEASURED — and `type = "cmd2"` escapes them. M13 added that cmd.exe expands `%VAR%` inside double quotes (true of cmd.exe, but never measured here, and it is the clause the conclusion actually rode on) and inferred from the pair a live analogue of the `$` bug. It is not one: MEASURED on Windows 11 build 26100 / R 4.6.1, all eight hostile names — `%TEMP%`, `^`, `&`, `!`, apostrophe, backtick, `$`, space — round-tripped through real ffmpeg and ffprobe intact under `cmd` quoting alone. `system2()` does not put `cmd.exe` in the loop on Windows, so there is no interpreter to expand them and `cmd2` would escape against a shell that is not there. The lesson to keep is the general one: what a shell *would* do to a string is not what *reaches the tool* — only a round trip through the real tool on the real platform answers that, and this claim stood in `LESSONS.md` and `DESIGN.md` for a day on inference alone.
- 2026-08-08 (M13): a platform-specific assertion folded into an otherwise platform-independent test passes locally and fails only on that platform's CI runner. Give it its own `test_that()` with the skip, so the portable assertions keep running everywhere — the mirror of M11's rule about skips taking a whole file down.
- 2026-08-08 (M16): a dead download link does not 404. All four of openac's OneDrive patch-expert URLs answered **HTTP 200 with a 34 KB `login.live.com` sign-in page**, so `download.file()` returned 0, the files existed and were non-empty, and the installer returned TRUE onto four HTML documents named `.dat` — for an unknown number of years. Status codes and existence checks cannot see this class; only the CONTENT can. Guard a downloaded artifact with a byte floor AND a markup sniff, and put `<!--` in the needles: the live.com page opens with a copyright comment, not `<!DOCTYPE`.
- 2026-08-08 (M16): when copying an upstream project's download URLs, take the ones it tries FIRST. OpenFace's `download_models` scripts try Dropbox and fall back to OneDrive; openac had copied only the fallback, and so inherited the half that died. Read the whole fallback chain before picking a link out of it.
- 2026-08-08 (M16): a mocked-download test suite is structurally blind to a dead URL — every green run of `test-installers.R` was compatible with all seven pinned links having rotted. A pinned external URL needs a periodic real fetch, opt-in and off by default, or it is unmeasured rather than working.
- 2026-08-08 (M13): `git add -A` after a failed or half-finished run commits its debris. It happened twice on one branch (12 zero-byte files from a vectorized `sub()`/`file.create()`, then a stray heredoc file), and `R CMD check` caught both as non-portable or non-standard top-level files — the record, not the author, is what noticed. Read `git status` before staging when anything has just errored.
- 2026-08-08 (M15): `shQuote(type = "cmd2")` is NOT a drop-in replacement for `"cmd"` — MEASURED, it prefixes `%`, `^`, `&` and `!` with `^` and adds NO quotes at all, so swapping to it splits any path containing a space. `?shQuote` says the two COMPOSE (`cmd` first, then `cmd2`), and the composition is wanted only when the command line actually reaches `cmd.exe` — which openac's `system2()` calls do not, so neither is.
- 2026-08-08 (M15): editing a file on the Windows host can rewrite it CRLF whole, so a two-line change lands as a four-hundred-line diff and `git blame` stops pointing at the milestone that wrote each line. `.gitattributes` (`* text=auto eol=lf`) now pins it — but that governs checkouts only: files already committed CRLF had to be renormalized once by hand, and adding the file alone would not have done it.
